# Architecture

This document describes the main decisions behind the portfolio and the parts worth understanding before making changes.

## Application flow

```text
Supabase content
      ↓
PortfolioContext
      ↓
Public sections ──────────────── Visitor Mode
      ↓
Host editing controls ───────── Host Mode
      ↓
Authenticated /api/content ──── Published content
```

`PortfolioContext` owns the published snapshot, current draft, undo history, redo history, Host state, and Preview state. Public components always render the current content object, which means Preview can display unsaved work without navigating away or replacing the Host session.

## Content model

`src/data/portfolio.js` defines the default data shape. Major collections include:

- profile and Hero content
- navigation and section visibility
- About items
- education stages and skill groups
- projects and competitions
- self-learning entries and strengths
- contact and social links

Collection items have stable IDs so editors can reorder or update them without relying on their current list position.

## Host Mode

Host Mode is layered above the visitor layout. Its global toolbar and Content Studio use fixed positioning, so editor controls do not alter section dimensions or move public content.

On desktop, the Content Studio is a draggable floating panel constrained to the viewport. On mobile, it becomes a bottom sheet to preserve natural touch scrolling.

Editing creates a local draft. The toolbar provides:

- **Undo / Redo** — move through draft history
- **Save** — publish the current draft
- **Discard** — restore the last saved snapshot
- **Preview** — hide editor UI without ending the Host session

## Authentication and persistence

Host authentication is handled by Vercel Functions in `api/host/`. Supabase issues the underlying access and refresh tokens, which the server returns as secure HTTP-only cookies.

The content endpoint performs three checks before writing:

1. The request uses the supported method.
2. The request origin matches the current host.
3. The Host session is valid or can be refreshed.

Only then is the `portfolio_content` record inserted or updated through Supabase REST.

## Styling

The site uses one fixed global background layer. Every content section remains transparent or translucent so the scene stays continuous while scrolling.

Responsive rules are grouped in the stylesheet layers under `src/styles/`. The newest revision file contains targeted adjustments that override earlier design layers without changing component structure.

## Deployment

The production build is generated by Vite and deployed on Vercel. Files under `api/` are deployed as serverless functions alongside the static frontend.
